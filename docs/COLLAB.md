# AI 辅助开发协作规约（新手团队版）

> 版本 v1.0（2026-11-05）。前提：团队 5 人均为新手开发者，日常编码高度依赖 AI Agent。
> 本文档的目标**不是教大家写代码**，而是约束「人和 Agent 的行为边界」，让 5 个人各自独立产出的代码能拼到一起。
> 本文档与 `docs/TEAM.md` 配套：TEAM.md 定「谁做什么」，本文档定「怎么做才能对接上」。

## 1. 先认清：新手 + Agent 的五个典型失败模式

| # | 症状（集成时才暴露） | 根因 |
|---|---|---|
| F1 | 前后端字段对不上：`kcal` vs `calories`、驼峰 vs 下划线 | 每人各自让 Agent「设计接口」，Agent 各自发明命名 |
| F2 | 各自模块单独跑都正常，一合并就编译不过 | Agent 各自升级依赖、改共享文件、引入不同的库 |
| F3 | 错误处理五花八门，前端无法统一写兜底 | 没有统一响应包络约定，Agent 按各自的习惯写 |
| F4 | 新手看不懂 Agent 产的代码，Code Review 形同虚设 | 缺少「新手也能执行」的检查清单 |
| F5 | Agent 卡住或开始瞎编，新手意识不到，硬着头皮提交 | 缺少「何时必须停下求助」的判据 |

**核心认知：Agent 的产出质量 ≈ 你喂给它的上下文质量。**
防对接失败的本质手段是：让所有人的 Agent 共享同一份契约上下文，并且把「对齐」交给工具（类型检查、CI），**而不是交给人眼**。以下六条防线全部围绕这一点。

## 2. 六条防线

### 防线 1 · 契约先行：共享类型包（把对齐交给编译器）

- 仓库根新增 `shared/` 目录，内容由 `docs/API.md` 固化成 TypeScript 类型：`Dish`、`Profile`、`Recommendation`、`ApiEnvelope`（统一响应包络）等，外加常量（忌口选项枚举、错误码表）。
- 前端和后端**只能 `import` 这一处的类型**，任何人不许在自己模块里手写同名 interface。
- 效果：字段名对不上在 `npm run build`（typecheck）阶段直接报错，**不用等到联调那天**。
- 维护人：BE-B。改 `shared/` = 改 `API.md`，必须走接口变更流程（见 API.md 附录）。

### 防线 2 · 目录所有权（从结构上避免合并冲突）

| 目录 / 文件 | 唯一所有者 |
|---|---|
| `web/src/views/`（建档 / 目标 / 推荐） | FE-A |
| `web/src/views/`（回填 / 反馈 / 历史）、`web/src/components/` | FE-B |
| `server/src/engines/` | BE-A |
| `server/src/services/` `llm/` `admin/`、`shared/`、根配置、CI | BE-B |
| `server/data/`、docs 需求与验收部分 | PD |

- 规则：需要动别人的目录 → 在群里 @ 所有者，**让所有者自己改**；不直接提交。
- `shared/`、`.env.example`、`package.json`、CI 配置属于全局文件，**非所有者的改动一律打回**。

### 防线 3 · 环境与依赖统一（一人管版本）

- Node 版本写死在 `.nvmrc`；**`package.json` 的依赖变更只允许出现在 BE-B 的 PR 里**。
- 统一脚本名，前后端一致：`npm run dev / test / smoke / seed`。
- Agent 建议安装新依赖时：不直接装，先问 BE-B，由 BE-B 统一评估后加入。

### 防线 4 · 集成自动化（每周集成不靠人肉对）

- Mock 与真实后端的切换**只改环境变量**（`VITE_API_BASE`），代码里禁止写死 URL——前端从 W1 起就能对着 Mock 开发，切真实接口零改码。
- 仓库提供两条自测命令：
  - 后端 `npm run smoke`：9 组端点各请求一遍，断言响应包络与字段（来自 API.md）；
  - 前端 `npm run e2e`：把原型 `_smoke.js` 的场景搬过来，跑通 建档→推荐→回填→反馈。
- CI 三件套每次 PR 必跑：**lint → typecheck → test**。CI 红了禁止合并——这是新手最省心的护栏，比任何人肉 Review 都可靠。
- 每周五「集成演示」：从 `main` 拉最新代码，当众跑通本周里程碑的那条验收链路。**演示的是运行效果，不是看代码**。

### 防线 5 · Agent 提示词规约（喂契约，不让它发明)

给 Agent 下任务时**必附的上下文**：

1. 本次任务对应的 `docs/API.md` 端点段落，或 `shared/types.ts` 相关类型；
2. 允许修改的目录（所有权）；
3. 完成标准（具体命令，如 `npm run test`）。

**禁止项**（固定贴在提示词末尾，团队成员统一使用）：

- 禁止新增 / 修改依赖，禁止改动 `shared/` 与根配置文件；
- 禁止改动接口字段命名与结构——要改先走接口变更流程；
- 禁止自创错误处理格式，必须使用统一响应包络 `ApiEnvelope`;
- 禁止绕过 lint / typecheck 提交。

**任务提示词模板**（复制即用）：

```
角色：你在为「食堂营养师」项目实现：<一句任务描述>。
契约：严格遵守以下类型 / 接口定义，字段名一字不改：
<粘贴 shared/types.ts 相关段落 或 docs/API.md 对应端点>
范围：只允许修改 <目录>，不改其他任何文件。
禁止：新增依赖；改 shared/；改接口结构；自定义错误格式。
完成标准：<验收命令> 通过；跑给我看输出。
```

### 防线 6 · 人工检查点（新手能执行的 Review）

PR 合并前，Reviewer 按三查清单过一遍（**不需要看懂代码逻辑**）：

1. **查契约**：打开本次 PR 涉及的 API.md 段落 / shared 类型，逐字段比对代码中的字段名拼写；
2. **查护栏**：CI 三件套全绿；PR 文件列表里没有越界文件（不是自己的目录、`shared/`、依赖）——有就直接打回；
3. **查行为**：本地按 PR 描述的验收命令 / 操作路径跑一遍，能看到预期结果。

**何时必须放弃 Agent、求助真人**（满足任一即停，不要硬耗）：

- 同一个报错反复修 3 次以上仍不通过；
- Agent 开始修改任务范围之外的文件（这是失控信号）；
- Agent 说「改一下接口 / 字段结构就能解决」→ 这不是代码问题，应走接口变更流程，由 BE-A 定夺。

## 3. 各角色的 Agent 使用边界

| 角色 | Agent 可自主做 | 必须人确认后合入 | 禁止交给 Agent |
|---|---|---|---|
| FE-A / FE-B | 页面布局、样式、组件实现、生成单测 | 字段绑定（对照 shared 类型逐个核）、路由与状态流转 | 改 shared 类型、自行定接口字段 |
| BE-A | 函数实现、测试用例、重构建议 | 算法权重 / 阈值调整（须对照原型断言跑测试） | 修改营养计算公式口径（须 PD 复核） |
| BE-B | 脚手架、CI 配置、部署脚本、Mock 数据 | 依赖版本升级、API 实现与契约对齐 | 允许他人绕过自己加依赖 |
| PD | 数据表格式转换、反推法计算辅助 | 每条营养数据入库前人工过目 | 让 Agent 批量凭空生成营养数值 |

## 4. 任务完成标准（Definition of Done）

每张任务卡五项全部打勾才算完成，缺一即退回：

1. ☐ 任务卡上的验收命令通过（test / smoke）；
2. ☐ CI 三件套（lint / typecheck / test）全绿；
3. ☐ PR 只包含自己所有权目录内的文件；
4. ☐ Reviewer 三查通过并 Approve；
5. ☐ 涉及接口的改动：`docs/API.md` 与代码完全同步，无未记载字段。

## 5. 对接失败速查表

| 症状 | 大概率根因 | 预防手段 |
|---|---|---|
| 前端取不到后端返回的字段 | 双方各自手写了类型 | 只从 `shared/` 导入类型（防线 1） |
| 本地各自正常，联调 400/500 | Mock 与真实实现的响应包络不一致 | smoke 脚本断言包络（防线 4） |
| 合并后编译崩 / 跑不起来 | 依赖版本漂移、共享文件冲突 | 目录所有权 + 依赖白名单（防线 2/3） |
| 前后端显示的数字对不上 | 前端偷偷做了营养计算 | 前端禁止任何营养数值计算（架构 D1，Agent 禁止项写明） |
| Agent 产出风格突变、看不懂 | 换了模型 / 没贴契约上下文 | 提示词模板 + 禁止项（防线 5） |

---

**一句话总结：所有人给 Agent 喂同一份契约，所有人提交前过同一道 CI，所有人的 PR 只动自己那块地——做到这三点，新手团队也能拼出一个能跑的系统。**
