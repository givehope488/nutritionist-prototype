# 分工安排

> 版本 v1.2（2026-11-05）。5 人团队：前端 ×2、后端 ×2、产品数据 ×1，**均为新手开发者、日常编码高度依赖 AI Agent**。
> **开发周期 3 周**（原 6 周方案经范围裁剪压缩而来，裁剪清单见 §3.4）：保「建档→推荐→回填→反馈」核心闭环，增值件全部后移。
> 开发行为规范见 `docs/COLLAB.md`（AI 辅助开发协作规约）：本文档定「谁做什么」，COLLAB.md 定「怎么做才能对接上」。两份都读，才算进入项目。

## 1. 角色定义

| FE-A | 前端 · 主流程 | 建档 / 目标与忌口 / 推荐页，与后端联调整条核心链路 |

### 3.4 范围裁剪清单（本次 6 周 → 3 周压缩掉的项，全部进 V2 需求池）

| 砍掉 / 后移项 | 处置 | 为什么可以这样砍 |
|---|---|---|
| LLM 文案层 | 上线后灰度接入 | 架构已支持 `TEXT_ENGINE` 一键切换，模板引擎先行，后移零返工 |
| 管理端 UI | W2 用 CLI 脚本替代 | 单人（PD）使用的工具不值得团队花一周做界面；修订留痕表保留 |
| 数据扩充至 100 道 | 只复核 55 道；上线后 PD 每周补 | 数据是长期资产，不该挤占 3 周工期 |
| 性能压测 | 砍 | 单校区量级（日活数百）远不需要 |
| 埋点与统计看板 | 只做 1 条采纳率统计接口，查数用 SQL | 看板是运营工具，上线初期人工查够用 |
| 30 人灰度 | 直接同学间小范围传播 | 用户就在身边，反馈链路更短 |

> **不可砍项**：CI 三件套、smoke 脚本、接口冻结流程、Reviewer 三查——新手团队砍质量护栏等于上线即事故。工期再紧，砍的永远是功能，不是护栏。

## 4. 关键依赖（提前盯）

1. **W1 是全局瓶颈**：接口冻结、`shared/` 类型包、Mock API 三样任何一样晚一天，五个人全部原地等待——W1 内只允许并行推进，不允许互相等待。
2. **数据种子**：W1 内 PD 完不成 55 道复核，W2 联调退回 Mock（可接受一次），但 W2 末验收硬依赖真实数据。
3. **LLM 层不在关键路径**：已整体后移出 3 周计划（见 §3.4），template 引擎即首版文案方案。
4. **3 周无缓冲**：任何任务预计延期 >2 天，当天在群里亮红并触发「砍范围」决策（按 §3.4 清表从上往下砍），不允许静默顺延。

## 5. 协作机制

### 5.1 例会与同步
- 每日 10 分钟站会（或异步群内接龙：昨天 / 今天 / 阻塞）
- 每周五里程碑评审（对照本文档验收标准，30 分钟）+ **集成演示**：从 main 拉最新代码，当众跑通本周验收链路——演示运行效果，不看代码
- 里程碑延期 >2 天须在群里说明并更新本文档

### 5.2 代码协作
- 分支：`main` 受保护；`feat/<模块>-<内容>` 短分支
- PR 须至少 1 人 Review，按 `docs/COLLAB.md` §6「三查清单」执行（新手可操作：查契约 / 查护栏 / 查行为）；引擎模块（`server/src/engines/`）PR 须 BE-A 之外再过 1 人
- **CI 三件套（lint / typecheck / test）不绿禁止合并**；禁止任何绕过检查的提交
- 提交信息：`模块: 做了什么`（如 `recommender: 增加小荤两阶段`）

### 5.3 接口变更流程
1. 提出人在 `docs/API.md` 提 PR（先改文档，不动代码）
2. 受影响的 FE/BE 两方 Review，24h 内响应
3. 合并后由后端在群里 @受影响方，约定切换时间
4. 兼容策略：新增字段直接加；修改/删除字段须保留一个版本的过渡期
5. **Agent 不得自行发起接口变更**：任何「改一下字段名/结构就能解决」的 Agent 建议都视为变更流程触发条件，人先评审

### 5.4 AI Agent 协作规约（详见 docs/COLLAB.md）
- 所有给 Agent 的任务提示必须附「契约上下文」（API.md 对应段落或 shared 类型），使用 COLLAB.md §5 的统一模板
- 目录所有权：只改自己目录，动别人的目录先 @ 所有者
- 依赖统一由 BE-B 管理；`.nvmrc` 锁 Node 版本
- 求助判据：同一报错修 3 次不过 / Agent 越界改文件 / Agent 提议改接口 → 停下来找人，不硬耗

### 5.5 文档维护责任
- `API.md` 归 BE-A；`ARCHITECTURE.md` 归 BE-B；`COLLAB.md` 归 BE-B（工具链与规约联动）；`TEAM.md`（本文档）归 PD；`README.md` 归 PD
- 文档失真视为缺陷，里程碑评审时抽查
