## 发现的问题

### P2-1 推荐补位质量：池子压缩时出现单菜极端补位（反馈 BE-A）

「减脂 + 不吃辣」下第一次推荐出现：
- 搭配二：**招牌口水鸡 260 kcal**（目标 750，-65%）
- 搭配三：**卤蛋 70 kcal**（目标 750，-90%）

A4 验收「至少 1 套 ≤10%」满足（套一 752/750），但把单菜当“一餐推荐”体验很差，且 **notice 未说明「缺少合适组合」**。
**建议**：`single`/`component` 补位时若偏离目标 > 40%，要么不出，要么在 notice 明确「适合当加餐/单点参考」。归 BE-A。

### P2-2 反馈页「暂无目标」文案（归 FE-B，P3）

脂肪/碳水/钠显示「31.6 g / 暂无目标」——引擎口径只比热量与蛋白，但「暂无目标」读起来像系统缺数据。
建议改为「仅供参考」或直接隐藏目标列。

### P2-3 回填页加载期摘要闪 JSON id（归 FE-B，P3）

预填刚进入时「4 项已选」摘要显示 `s01、m10、v06…`（菜品 id），菜单加载完成后变菜名。建议加载中显示骨架或菜名占位。

### 流程问题：默认走 Mock，手动走查易误判

`client.ts` 的 `VITE_API_BASE ?? 'mock://local'`：**不设环境变量会静默走 Mock**。本次第一轮走查即因此误判「回填页空态」为产品 bug（Mock 午餐菜单不全）。
建议在 `web/.env.example` 与 README 明确：**手动走查必须 `VITE_API_BASE= npm run dev`（空值）**，或把默认值改为同源代理。
