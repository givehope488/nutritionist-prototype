## 2. 营养数值的内部一致性

用 Atwater 系数（蛋白 4 / 脂肪 9 / 碳水 4）反算热量，与标注值比对：

```
|偏差| > 15%: 0 条
|偏差| > 10%: 1 条（b02 无糖豆浆 -11.3%）
最大偏差: 11.3%
```

结论：**这批数值内部自洽，不是随手编的**。但它们仍全部是 `reliability: B`（反推/估算），绝对份量是否对得上食堂实际供应，只能靠配料反推复核，脚本判断不了。

**两条必须让 BE-A 知道的结论：**

1. **素食 + 忌麸质 → 早餐主食只剩「白粥」1 道。** 早餐 4 道素主食里 3 道（菜包、油条、煎饼果子）带 `gluten`。这直接支撑 FE-A 的 Y3（无解引导）——不是理论上的边界，是高频组合。
2. **素食下午餐只剩 23/41 道，其中主食 8 道里 3 道含麸质。** 素食学生的可选面明显窄，推荐引擎在素食场景下必须能跨类别补位，否则「凑不齐一餐」会成为常态。

## 5. 剩余工作：55 条配料反推（这才是 W1 的硬活）

底稿已生成，55 行，每行已填好：id / 菜名 / 分类 / 餐段 / 旧标签 / 新展示用语 / 迁移克重 / 克重来源 / 标注 kcal / Atwater 算得 / 偏差% / tags。**空着的四列是你要填的：配料清单、克重依据、复核结论、复核人+日期。**

填法（每条约 3 分钟）：

1. 从菜名拆配料，例如「红烧肉 150g」→ 猪五花 120g + 酱油 8g + 糖 6g + 油 10g；
2. 每个配料查《中国食物成分表》标准值，按克重加权求和；
3. 与现有 `kcal / protein_g / fat_g / carbs_g / sodium_mg` 对比，偏差 >15% 的改数并把 `reliability` 降为 `C`；
4. 把配料写进种子的 `ingredients`（格式 `{"name":"猪五花","grams":120,"source":"中国食物成分表 第6版"}`），**同时**在 CSV 留一行记录。

节奏：**11 条/天 × 5 天**，11-06 起至 11-10 完成。改完跑 `npm run check:data`，它会拦住四类错误：份量标签带克重、tag 不在枚举内、含 pork/beef 缺 meat、A 级缺配料依据、热量与三大营养素偏差 >25%。

## 6. 我没有替你生成营养数值

COLLAB.md §3 明令「禁止让 Agent 批量凭空生成营养数值」。这份文档只做三件事：结构迁移、能机器判定的错误修正、把判断依据整理成一屏能看完的表格。**每一条配料和克重必须由你确认来源**——一旦由我编，55 条会全部变成"看起来有依据、实际无法溯源"，比现在的 B 级更糟。
